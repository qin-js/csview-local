### 虚函数是怎么实现多态的？<Badge text="重要" type="danger" />

每个含虚函数的类在编译期生成一张**虚函数表 vtable**，表里是函数地址；每个对象头部隐含一个 **vptr** 指向所属类的 vtable。

调用 `p->f()` 时，编译器生成的代码是「取对象的 vptr → 在表里按固定槽位取地址 → 间接调用」。**槽位在编译期确定，具体地址在运行期确定**，这就是动态绑定。

由此可以推出几个常考结论：

- 构造函数不能是虚函数：vptr 还没初始化好，无法查表。
- **析构函数应该是虚函数**：否则 `delete basePtr` 只会调基类析构，派生类成员泄漏。
- 构造 / 析构函数内部调用虚函数不会分派到派生类，因为此刻 vptr 指向的是当前正在构造的那一层。
- 虚函数调用无法内联（除非编译器能去虚化），有间接跳转开销。

### 重载、重写、隐藏的区别？<Badge text="掌握" type="tip" />

- **重载 overload**：同一作用域内，函数名相同、参数列表不同。编译期按实参类型选，与虚函数无关。
- **重写 override**：派生类覆盖基类的**同签名虚函数**，运行期分派。C++11 起加 `override` 关键字让编译器帮你检查签名。
- **隐藏 hide**：派生类定义了同名函数（不管参数是否相同），基类同名函数**全部**被隐藏，不是重载。想保留基类版本要 `using Base::f;`。

::: warning 最容易踩的坑
基类 `virtual void f(int)`，派生类写成 `void f(double)`，你以为在重写，其实是隐藏 + 新函数。加上 `override` 会直接编译报错，把这个 bug 拦在编译期。
:::

### 智能指针怎么选？<Badge text="重要" type="danger" />

- `unique_ptr`：独占所有权，不可拷贝只可移动，零额外开销，**默认首选**。
- `shared_ptr`：引用计数共享所有权，控制块含强/弱两个计数，计数操作是原子的，有开销。
- `weak_ptr`：不增加强计数，用 `lock()` 提升为 `shared_ptr`，专门用来**打破循环引用**。

::: danger 循环引用
两个对象各持对方的 `shared_ptr`，强计数永远降不到 0，双双泄漏。典型场景是父子互指、观察者与被观察者互指。解法是把「反向引用」改成 `weak_ptr`，明确谁拥有谁。
:::

另外注意：`shared_ptr` 的**控制块线程安全，被管理对象不是**；多线程读写同一个对象仍需自己加锁。`make_shared` 把控制块和对象合并成一次分配，比 `shared_ptr<T>(new T)` 少一次分配，但对象内存要等所有 `weak_ptr` 释放才归还。

### 移动语义解决了什么问题？<Badge text="掌握" type="tip" />

拷贝一个持有堆资源的对象要重新分配并逐字节复制，而临时对象马上就要销毁，这份复制纯属浪费。移动语义把资源的**所有权直接转移**，把源对象置空，代价从 O(n) 降到 O(1)。

```cpp
class Buffer {
    char*  data_ = nullptr;
    size_t size_ = 0;
public:
    Buffer(Buffer&& o) noexcept
        : data_(o.data_), size_(o.size_) {
        o.data_ = nullptr;      // 交出所有权，源对象必须可安全析构
        o.size_ = 0;
    }
    Buffer& operator=(Buffer&& o) noexcept {
        if (this != &o) {
            delete[] data_;
            data_ = o.data_; size_ = o.size_;
            o.data_ = nullptr; o.size_ = 0;
        }
        return *this;
    }
    ~Buffer() { delete[] data_; }
};
```

::: tip 为什么要标 noexcept
`std::vector` 扩容时只有确认元素的移动构造是 `noexcept` 才敢用移动，否则为了异常安全会退回拷贝。漏写 `noexcept` 会让容器性能悄悄退化。
:::

### 堆和栈的区别？<Badge text="掌握" type="tip" />

- **管理方式**：栈由编译器自动分配释放，堆由程序员或智能指针管理。
- **生命周期**：栈随作用域结束即回收；堆到显式释放为止。
- **分配成本**：栈只是移动栈指针，几条指令；堆要走分配器，可能加锁、可能触发系统调用。
- **碎片**：栈连续无碎片；堆频繁分配释放会产生外部碎片。
- **容量**：栈通常几 MB，递归过深或大数组会栈溢出；堆受进程地址空间限制，大得多。
- **缓存局部性**：栈上对象紧凑，命中率天然更高。

所以性能敏感的短生命周期小对象优先放栈上，大对象或需要跨作用域存活的才放堆。
